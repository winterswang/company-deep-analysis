# Company Deep Analysis V6.2 需求文档

## 一、项目概述

### 1.1 项目名称
Company Deep Analysis Skill V6.2

### 1.2 项目目标
开发一个高质量的投资分析工具，实现：
- 严格的数据质量控制
- 辩证式分析过程
- 结构化投资报告输出

### 1.3 核心原则
1. **数据质量第一**：P2以下数据丢弃，数据不足时退出
2. **聚焦企业本身**：不陷入元数据问题
3. **辩证过程透明**：展示每个模块的挑战→解答过程
4. **输出结构化**：7个章节 + 数据引用报告

## 二、数据源配置

### 2.1 数据源质量等级

| 等级 | 定义 | 数据源 | 处理方式 |
|------|------|--------|----------|
| **P0** | 官方一手数据 | AkShare、雪球爬虫、本地数据 | ✅ 直接使用 |
| **P1** | 权威第三方 | Bloomberg、Reuters、S&P | ✅ 直接使用 |
| **P2** | 专业机构 | 行业协会、研究机构 | ✅ 需验证 |
| **P3** | 媒体报道 | 财经媒体、分析师报告 | ❌ 丢弃 |
| **P4** | 未验证/估算 | 网络搜索、推断 | ❌ 丢弃 |

### 2.2 数据源优先级

```
1. AkShare (P0) - 财务数据
2. 雪球爬虫 (P0) - 专业分析
3. 本地数据 (P0) - 用户收藏
4. Tavily (P2) - 搜索引擎
5. Exa (P2) - 深度搜索
```

### 2.3 数据充足标准

| 数据类型 | 最少数量 | 必需项 |
|----------|----------|--------|
| 财务数据 | 5条 | 营收、净利润、ROIC/ROE、毛利率、现金流 |
| 估值数据 | 2条 | 市值、P/E或P/B |
| 业务数据 | 2条 | 主营业务、行业 |
| **总计** | **≥8条** | 有效数据（P2及以上）|

## 三、数据质量控制

### 3.1 数据检查流程

```
输入数据
    ↓
质量检查（P0-P4分级）
    ↓
P2及以上 → 保留
P3及以下 → 丢弃
    ↓
数量检查
    ↓
≥8条有效 → 继续分析
<8条有效 → 终止分析，输出原因
```

### 3.2 数据不足时的处理

当有效数据不足时，必须：
1. **明确终止原因**：说明缺少哪些数据
2. **列出有效数据**：已获取的P2及以上数据
3. **列出丢弃数据**：P3及以下数据及丢弃原因
4. **给出补充建议**：建议从哪些数据源获取

### 3.3 数据标注要求

每个数据项必须包含：
- 数据名称
- 数据值
- 来源（具体到网站/报告）
- 质量等级（P0-P4）
- 获取时间
- 时效性（如：FY2024、TTM）
- 备注

## 四、辩证式分析框架

### 4.1 双角色协作

```
【主链路】分析师（Analyst）
- 生成投资分析报告
- 响应挑战者的建议
- 执行改进ToDo
- 输出最终报告

【副链路】挑战者（Challenger）
- 阅读分析报告
- 提出改进建议
- 给出具体ToDo
- 评估改进效果
```

### 4.2 否定之否定过程

```
初始版本（正题）
    ↓ 挑战者质疑（反题/否定）
解答后的终稿（合题/否定之否定）
    → 更高质量的分析
```

### 4.3 挑战者要求

**有效挑战领域**：
- 财务分析深度
- 护城河本质分析
- 估值合理性
- 风险评估充分性
- 数据支撑

**无效挑战领域**：
- 元数据（CIK编号、文件格式等）
- 已充分讨论的内容

### 5.1 主报告结构

```markdown
# {公司名} 投资价值分析报告

## 📊 数据质量概览
（数据来源表格、质量评估）

## 一、执行摘要
### 【初始版本】
### 【挑战点】
### 【解答】
### 【最终版本】

## 二、业务分析
（同上结构）

## 三、财务质量分析
（同上结构）

## 四、竞争格局
（同上结构）

## 五、管理层分析
（同上结构）

## 六、估值分析
（同上结构）

## 七、投资决策
（同上结构）

## 📎 附录：数据引用报告
（数据来源清单、质量评估、时效性说明）
```

### 5.2 数据引用报告

必须包含：
1. **数据来源清单**：表格形式，每个数据的来源、质量、时效性
2. **数据质量评估**：完整性、时效性、可信度评分
3. **数据时效性说明**：解释为何缺少最新数据
4. **建议补充数据**：指导用户如何改进

## 六、技术实现

### 6.1 核心文件

| 文件 | 功能 |
|------|------|
| `core/analyzer_v62.py` | 主分析器，数据质量控制 |
| `config/data_sources_v62.py` | 数据源配置 |
| `scripts/data_collector_v62.py` | 数据收集器 |
| `core/llm_client.py` | LLM客户端 |

### 6.2 数据结构

```python
@dataclass
class DataPoint:
    name: str           # 数据名称
    value: Any          # 数据值
    source: str         # 数据来源
    quality: str        # 质量等级 P0-P4
    timestamp: str      # 获取时间
    validity: str       # 时效性
    notes: str          # 备注
```

### 6.3 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| min_valid_data | 8 | 最少有效数据数 |
| score_threshold | 85 | 报告质量阈值 |
| max_iterations | 5 | 最大辩证轮数 |
