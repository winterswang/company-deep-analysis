# Company Deep Analysis V6.3 需求文档

## 一、项目概述

### 1.1 项目名称
Company Deep Analysis Skill V6.3

### 1.2 项目目标
开发一个高质量的投资分析工具，实现：
- 严格的数据质量控制
- **辩证式分析过程（否定之否定）**
- 结构化投资报告输出
- 每个章节展示：初始版本→挑战点→解答→最终版本

### 1.3 核心原则
1. **数据质量第一**：P2以下数据丢弃，数据不足时退出
2. **聚焦企业本身**：不陷入元数据问题
3. **辩证过程透明**：展示每个模块的挑战→解答过程
4. **输出结构化**：7个章节 + 数据引用报告

---

## 二、数据源配置

### 2.1 数据源质量等级

| 等级 | 定义 | 数据源 | 处理方式 |
|------|------|--------|----------|
| **P0** | 官方一手数据 | AkShare、雪球爬虫、本地数据 | ✅ 直接使用 |
| **P1** | 权威第三方 | Bloomberg、Reuters、S&P | ✅ 直接使用 |
| **P2** | 专业机构 | 行业协会、研究机构 | ✅ 需验证 |
| **P3** | 媒体报道 | 财经媒体、分析师报告 | ❌ 丢弃 |
| **P4** | 未验证/估算 | 网络搜索、推断 | ❌ 丢弃 |

### 2.2 雪球数据质量评估规则 ⭐

| 数据类型 | 质量判断标准 | 质量等级 |
|----------|--------------|----------|
| **专栏文章** | 内容≥300字符 | P0 |
| **专栏文章** | 内容<300字符 | P2 |
| **公告** | 固定 | P1 |
| **资讯** | 标题≥20字符 | P2 |
| **讨论** | < 50字符 | P4（丢弃） |
| **讨论** | 50-150字符 | P3（丢弃） |
| **讨论** | 150-300字符 | P2 |
| **讨论** | > 300字符 | P1 |

### 2.3 数据充足标准

| 数据类型 | 最少数量 | 必需项 |
|----------|----------|--------|
| 财务数据 | 5条 | 营收、净利润、ROIC/ROE、毛利率、现金流 |
| 估值数据 | 2条 | 市值、P/E或P/B |
| 业务数据 | 2条 | 主营业务、行业 |
| **总计** | **≥8条** | 有效数据（P2及以上）|

## 三、数据质量控制

### 3.1 数据检查流程

```
输入数据
    ↓
质量检查（P0-P4分级）
    ↓
P2及以上 → 保留
P3及以下 → 丢弃
    ↓
数量检查
    ↓
≥8条有效 → 继续分析
<8条有效 → 终止分析，输出原因
```

### 3.2 数据不足时的处理

当有效数据不足时，必须：
1. **明确终止原因**：说明缺少哪些数据
2. **列出有效数据**：已获取的P2及以上数据
3. **列出丢弃数据**：P3及以下数据及丢弃原因
4. **给出补充建议**：建议从哪些数据源获取

## 四、辩证式分析框架 ⭐⭐⭐

### 4.1 核心方法论

**否定之否定**：
```
正题（初始版本）
    ↓ 质疑/挑战（反题）
合题（改进后的最终版本）
    → 更高质量的分析
```

### 4.2 双角色协作

```
┌─────────────────────────────────────────────────────────────┐
│                    双角色协作架构                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   【主链路】分析师（Analyst）                                 │
│   - 生成投资分析报告                                         │
│   - 响应挑战者的质疑                                         │
│   - 执行改进ToDo                                             │
│   - 输出最终报告                                             │
│                                                             │
│                     ↕ 辩证对话                               │
│                                                             │
│   【副链路】挑战者（Challenger）                              │
│   - 阅读分析报告                                             │
│   - 识别分析薄弱环节                                         │
│   - 提出具体挑战点                                           │
│   - 给出改进ToDo                                             │
│   - 评估报告质量（打分）                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 分析流程（详细版）⭐⭐⭐

```
【第1轮：初始分析】
1. 数据收集 → 生成初始数据集
2. 分析师生成初始报告（V1）
3. 挑战者评估V1：
   - 识别薄弱环节
   - 提出挑战点（具体、可验证）
   - 给出ToDo列表（包含数据检索需求）
4. 执行ToDo：
   a. 从现有数据中找新依据（重新审视已收集数据）
   b. 新数据检索（Tavily/Exa搜索）
   c. 本地数据检索（用户收藏、历史报告）
   d. 数据质量评估（P0-P4分级）
5. 分析师基于新证据改进报告（V2）

【第2轮：深化分析】
1. 挑战者评估V2：
   - 验证之前的挑战是否已解决
   - 发现新的薄弱环节
   - 提出更具体的挑战点
2. 执行ToDo：
   - 聚焦搜索（关键词更具体）
   - 深度验证（交叉验证关键数据）
   - 补充证据链
3. 分析师改进报告（V3）

【第N轮：收敛分析】
每轮迭代：
- 问题范围更聚焦
- 证据链更完整
- 分析更深入

终止条件：
- 挑战者评分 >= 85分
- 或达到最大轮数（5轮）
- 或无新挑战点
```

### 4.4 ToDo执行流程 ⭐⭐⭐

```
ToDo类型：
├─ 数据验证类
│   ├─ 从现有数据中重新提取依据
│   ├─ 交叉验证关键数据
│   └─ 标注数据来源和质量
│
├─ 数据检索类
│   ├─ Tavily搜索（实时新闻）
│   ├─ Exa深度搜索（研究报告）
│   ├─ 雪球搜索（专业观点）
│   └─ 本地数据检索（用户收藏）
│
├─ 分析深化类
│   ├─ 财务数据拆解
│   ├─ 护城河本质分析
│   ├─ 估值模型调整
│   └─ 风险细化
│
└─ 证据补充类
    ├─ 原文引用标注
    ├─ 数据来源链接
    └─ 置信度评估
```

### 4.5 迭代深化示例

**第1轮挑战**：
```
挑战点："ROIC 18.5%"只是一个数字，缺乏趋势分析

ToDo:
- 检索：搜索Nintendo ROIC 5年趋势
- 验证：确认18.5%的计算方法
- 分析：ROIC变化的驱动因素
```

**执行ToDo**：
```
1. Tavily搜索："Nintendo ROIC trend 5 years"
2. 从搜索结果提取：
   - 2020: 15.2% → 2024: 18.5%
   - 驱动因素：软件收入占比提升
3. 数据质量：P2（财经网站）
```

**第2轮改进报告**：
```
ROIC从15.2%（2020）提升至18.5%（2024），主因：
- 软件业务占比从40%→68%
- 毛利率提升（硬件32% vs 软件92%）
[P2] 来源：Tavily搜索结果
```

**第2轮挑战**：
```
挑战点：软件占比提升是驱动因素，但缺乏竞争对比

ToDo:
- 检索：Sony/Microsoft软件占比对比
- 分析：任天堂软件业务独特性
```

**执行ToDo**：
```
1. Exa搜索："Nintendo vs Sony software revenue percentage"
2. 发现：索尼软件占比仅30%，任天堂68%
3. 分析：任天堂IP护城河更强
```

**第3轮改进报告**：
```
任天堂软件占比68%显著高于索尼（30%），体现：
- IP护城河：独占游戏占软件收入85%
- 定价权：第一方游戏ASP ¥7,980
[P1] 来源：Exa深度研究
```

### 6.2 分析器核心逻辑

```python
class DialecticalAnalyzerV63:
    def analyze(self, company, data):
        report = self.analyst.generate_initial_report(data)
        
        for round in range(max_iterations):
            # 挑战者评估
            challenges, score, todos = self.challenger.evaluate(report)
            
            if score >= 85:
                break
            
            # 分析师改进
            report = self.analyst.improve(report, challenges, todos)
        
        return self.generate_final_report_with_dialectic_process()
```

| score_threshold | 85 | 终止阈值 |
| max_iterations | 5 | 最大辩证轮数 |
