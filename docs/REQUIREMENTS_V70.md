# Company Deep Analysis V7.0 需求文档

## 一、项目概述

### 1.1 项目名称
Company Deep Analysis Skill V7.0

### 1.2 项目目标
开发一个高质量的投资分析工具，实现：
- **财务数据质量验证（否定之否定）**
- **五层追问模型（财务数据→经营表现→经营能力→护城河来源→不可复制性）**
- **奖励函数驱动的深度分析**
- **循环追问机制（追问→ToDo→数据检索→新证据→继续追问）**
- 结构化投资报告输出

### 1.3 核心原则

1. **数据质量第一**：财务数据必须经过否定之否定验证
2. **追问驱动**：每一层追问都产生ToDo，驱动数据收集
3. **洞察本质**：透过财务数据看到企业经营本质
4. **证据支撑**：每个结论都有数据支撑
5. **接受漫长**：追求高质量，接受分析过程的漫长和复杂

### 1.4 核心理念

**财务数据的本质映射**：

```
┌─────────────────────────────────────────────────────────────┐
│              财务数据 → 企业本质 映射关系                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   财务数据                      企业本质                     │
│   ────────                      ────────                     │
│                                                             │
│   营收增速        →           市场需求 + 产品竞争力          │
│                                                             │
│   毛利率          →           定价权 + 成本控制能力          │
│                                                             │
│   ROIC/ROE       →           资本配置能力 + 商业模式质量     │
│                                                             │
│   现金流          →           盈利质量 + 经营健康度          │
│                                                             │
│   应收账款周转    →           对下游议价权                   │
│                                                             │
│   存货周转        →           对市场判断力 + 供应链效率      │
│                                                             │
│   应付账款周转    →           对上游议价权                   │
│                                                             │
│   研发投入占比    →           创新能力 + 长期竞争力          │
│                                                             │
│   销售费用率      →           品牌力 + 渠道效率              │
│                                                             │
│   管理费用率      →           组织效率                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**财务数据反映的是企业的经营状况，是企业的经营能力，企业的护城河和竞争优势，管理层执行力和文化，构成了企业目前的经营数据以及对应的趋势变化。**

## 三、财务数据质量验证（否定之否定）⭐⭐⭐

### 3.1 核心理念

**财务数据的准确性和质量是整个分析的基石。必须通过"否定之否定"的分析，确认数据质量。**

### 3.2 验证流程

```
┌─────────────────────────────────────────────────────────────┐
│              财务数据质量验证（否定之否定）                   │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第一步：收集初始财务数据                                    │
│  ├─ 来源1：年报/10-K（P0）                                  │
│  ├─ 来源2：AkShare财务接口（P0）                            │
│  ├─ 来源3：雪球财务数据（P1）                               │
│  └─ 来源4：Tavily搜索（P2）                                 │
│       ↓                                                     │
│  第二步：否定（质疑数据质量）                                │
│  ├─ 质疑1：数据来源是否可靠？                               │
│  │   → 检查：是否来自官方披露？                             │
│  │   → 验证：年报原文页码引用                               │
│  │                                                          │
│  ├─ 质疑2：数据是否一致？                                   │
│  │   → 检查：不同来源的数据是否匹配                         │
│  │   → 验证：交叉对比                                       │
│  │                                                          │
│  ├─ 质疑3：数据是否完整？                                   │
│  │   → 检查：关键指标是否齐全                               │
│  │   → 验证：5年数据是否连续                                │
│  │                                                          │
│  └─ 质疑4：数据是否可解释？                                 │
│      → 检查：异常数据是否有合理原因                         │
│      → 验证：查找管理层解释                                 │
│       ↓                                                     │
│  第三步：否定之否定（确认数据质量）                          │
│  ├─ 通过验证的数据：标记为"可信"                            │
│  ├─ 未通过验证的数据：标记为"待验证"                        │
│  └─ 无法验证的数据：标记为"不可用"                          │
│       ↓                                                     │
│  输出：财务数据质量报告                                      │
│  ├─ 可信数据：XX条                                          │
│  ├─ 待验证数据：XX条                                        │
│  └─ 数据质量评分：X/10                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 数据质量评分体系

```
┌─────────────────────────────────────────────────────────────┐
│              财务数据质量评分体系                            │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  评分维度：                                                  │
│                                                             │
│  1. 来源可靠性（0-3分）                                      │
│  - 官方年报：3分                                            │
│  - 官方公告：2.5分                                          │
│  - 权威第三方（Bloomberg等）：2分                            │
│  - 一般第三方：1分                                          │
│  - 未知来源：0分                                            │
│                                                             │
│  2. 交叉验证（0-3分）                                        │
│  - 多源一致：3分                                            │
│  - 单源但有原文引用：2分                                    │
│  - 单源无引用：1分                                          │
│  - 无法验证：0分                                            │
│                                                             │
│  3. 时效性（0-2分）                                          │
│  - 最新季度：2分                                            │
│  - 最近一年：1.5分                                          │
│  - 1-2年：1分                                               │
│  - >2年：0.5分                                              │
│                                                             │
│  4. 完整性（0-2分）                                          │
│  - 5年连续：2分                                             │
│  - 3年连续：1.5分                                           │
│  - 1-2年：1分                                               │
│  - 仅单季度：0.5分                                          │
│                                                             │
│  总分：0-10分                                                │
│  - >=8分：高质量（可直接使用）                               │
│  - 6-7分：中等质量（需标注）                                 │
│  - <6分：低质量（需补充验证）                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.4 验证示例

```
【收集初始数据】

数据项：ROIC
- 来源1：雪球讨论 → 18.5%（P2）
- 来源2：Tavily搜索 → 32.7%（P2）
- 来源3：年报计算 → 需要原始数据

【否定：质疑数据质量】

质疑：ROIC数据差异巨大（18.5% vs 32.7%），哪个是对的？

验证过程：
1. 检查雪球讨论来源
   - 原文："ROIC 18.5%"
   - 问题：无计算过程，来源不明

2. 检查Tavily搜索来源
   - 原文："ROIC 32.7%"
   - 来源：Simply Wall St
   - 问题：第三方计算，需验证

3. 自己计算验证
   - 需要数据：NOPAT、Invested Capital
   - 触发ToDo：获取年报中的NOPAT和Invested Capital明细

【执行ToDo】

ToDo: 从PDD 2025 Q3 10-Q中提取：
  - Non-GAAP Net Income
  - Tax-Adjusted SBC
  - Total Equity
  - Interest-Bearing Debt
  - Excess Cash

结果：
  - NOPAT = 24.3B + 3.21B + 1.36B = 28.87B
  - Invested Capital = 129.3B + 0 - 290.3B = 89.05B
  - ROIC = 28.87 / 89.05 = 32.4%

【否定之否定：确认质量】

结论：
  - 雪球数据18.5%：错误（可能是旧数据或计算方法不同）
  - Tavily数据32.7%：接近正确（32.4%）
  - 自己计算32.4%：正确（有完整计算过程）

数据质量评分：
  - 来源可靠性：2分（年报计算）
  - 交叉验证：2分（多源对比后确认）
  - 时效性：2分（最新季度）
  - 完整性：1.5分（单个季度）
  - 总分：7.5/10（中等偏高）

标记：ROIC 32.4% [可信]
```

## 四、五层追问模型 ⭐⭐⭐

### 4.1 核心框架

```
┌─────────────────────────────────────────────────────────────┐
│              五层追问：从结果到本质                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  第1层：财务数据（结果）                                     │
│  例：ROIC 42%                                               │
│       ↓ 为什么ROIC高？                                      │
│                                                             │
│  第2层：经营表现（直接原因）                                 │
│  例：现金周转周期-127天，资本效率高                          │
│       ↓ 为什么资本效率高？                                   │
│                                                             │
│  第3层：经营能力（能力层）                                   │
│  例：对供应链的资金控制能力                                  │
│       ↓ 为什么有这个能力？                                   │
│                                                             │
│  第4层：护城河来源（竞争优势）                               │
│  例：规模效应？转换成本？网络效应？成本优势？                │
│       ↓ 哪一个？为什么？                                    │
│                                                             │
│  第5层：护城河本质（不可复制性）                             │
│  例：这个优势为什么竞争对手无法复制？                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 每层追问的处理

| 层级 | 问题类型 | 可能产生的ToDo | 数据来源 |
|------|----------|----------------|----------|
| 第1层 | 财务数据为什么是这样？ | 财务数据验证、年报查询 | AkShare、年报、雪球 |
| 第2层 | 经营表现为什么是这样？ | 行业对比、历史趋势分析 | AkShare、雪球、Exa搜索 |
| 第3层 | 经营能力来源是什么？ | 业务模式分析、流程研究 | 雪球专栏、Tavily搜索、本地数据 |
| 第4层 | 护城河是哪个类型？ | 竞品对比、护城河验证 | AkShare、Exa搜索、雪球、本地数据 |
| 第5层 | 为什么不可复制？ | 竞争格局分析、路径依赖分析 | Exa深度搜索、Tavily搜索、本地数据 |

**数据源说明**：

| 数据源 | 适用场景 | 质量等级 | 使用方式 |
|--------|----------|----------|----------|
| **AkShare** | 财务数据、行情数据、行业数据 | P0 | API直接调用 |
| **雪球** | 讨论观点、专栏文章、公告、资讯 | P0-P2 | 爬虫获取 |
| **Exa** | 深度研究报告、行业分析 | P2 | API搜索 |
| **Tavily** | 实时新闻、市场动态 | P2 | API搜索 |
| **本地数据** | 用户收藏、历史报告、已下载文件 | P0-P1 | 本地文件读取 |

## 五、护城河类型体系（巴菲特/晨星分类）⭐⭐⭐

### 5.1 五大护城河来源

```
┌─────────────────────────────────────────────────────────────┐
│              护城河五大来源（巴菲特/晨星分类）                │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 网络效应                                                │
│     定义：用户越多，价值越大                                │
│     财务表现：获客成本下降、用户留存率上升                   │
│     案例：微信、淘宝、美团                                   │
│     追问：新用户加入是否让所有用户受益？                     │
│                                                             │
│  2. 转换成本                                                │
│     定义：更换供应商的成本/风险很高                          │
│     财务表现：客户留存率高、提价能力强                       │
│     案例：苹果生态、企业软件、银行                           │
│     追问：客户换掉我们会损失什么？                           │
│                                                             │
│  3. 成本优势                                                │
│     定义：能以更低成本提供相同产品/服务                      │
│     财务表现：毛利率高于同行                                 │
│     案例：沃尔玛、亚马逊、Costco                             │
│     追问：低成本来自规模、地理位置、独特资源还是流程？       │
│                                                             │
│  4. 无形资产                                                │
│     定义：品牌、专利、牌照、监管准入                         │
│     财务表现：溢价定价能力、市场独占                         │
│     案例：茅台、可口可乐、专利药企                           │
│     追问：这个无形资产有定价权吗？能持续吗？                  │
│                                                             │
│  5. 有效规模                                                │
│     定义：市场规模只够容纳少数竞争者                         │
│     财务表现：高ROIC、低竞争                                 │
│     案例：机场、铁路、公用事业                               │
│     追问：新进入者会破坏均衡吗？                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 护城河验证问题清单

| 护城河类型 | 核心问题 | 验证数据 |
|------------|----------|----------|
| 网络效应 | 新用户加入是否让所有用户受益？ | 获客成本趋势、用户留存率、GMV增速 |
| 转换成本 | 客户换掉我们会损失什么？ | 客户留存率、续约率、提价能力 |
| 成本优势 | 低成本来自哪里？ | 毛利率、成本结构、单位成本趋势 |
| 无形资产 | 品牌/专利能带来定价权吗？ | 溢价定价能力、品牌价值、专利数量 |
| 有效规模 | 新进入者会破坏均衡吗？ | ROIC、竞争者数量、市场集中度 |

## 六、奖励函数设计 ⭐⭐⭐

### 6.1 核心目标

**奖励函数目标：驱动分析不断追问"为什么"，直到定位到护城河的本质来源。**

**透过各种经营数据，挖掘最核心的数据和趋势变化，回答这个现象的本质内核。**

### 6.2 奖励函数公式

```
R = Σ(层级深度 × 证据强度 × 不可复制性)

层级深度（问到第几层）：
- 第1层（财务数据）：1分
- 第2层（经营表现）：2分
- 第3层（经营能力）：3分
- 第4层（护城河来源）：4分
- 第5层（不可复制性）：5分

证据强度（是否有数据支撑）：
- P0数据：1.0
- P1数据：0.8
- P2数据：0.6
- 无证据：0.0

不可复制性（护城河可持续性）：
- 强不可复制（5年以上）：1.0
- 中等（3-5年）：0.7
- 弱（1-3年）：0.4
- 可复制（<1年）：0.1
```

### 6.3 触发机制

```
发现异常 → 提出假设 → 收集证据 → 验证/修正假设
```

## 七、循环追问机制 ⭐⭐⭐

### 7.1 循环流程

```
┌─────────────────────────────────────────────────────────────┐
│                    追问循环机制                              │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   当前层追问 ──────────────────────────────────────┐        │
│       │                                            │        │
│       ↓                                            │        │
│   发现问题/异常                                    │        │
│       │                                            │        │
│       ↓                                            │        │
│   生成ToDo                                         │        │
│       │                                            │        │
│       ├─→ ToDo类型1：数据检索                       │        │
│       │       └→ Tavily/Exa搜索                   │        │
│       │                                            │        │
│       ├─→ ToDo类型2：本地数据查询                  │        │
│       │       └→ 用户收藏/历史报告                 │        │
│       │                                            │        │
│       ├─→ ToDo类型3：爬取数据                      │        │
│       │       └→ 雪球/年报网站                    │        │
│       │                                            │        │
│       └─→ ToDo类型4：深度分析                      │        │
│               └→ LLM深度推理                      │        │
│       │                                            │        │
│       ↓                                            │        │
│   获取新证据                                       │        │
│       │                                            │        │
│       ↓                                            │        │
│   验证新证据质量                                   │        │
│       │                                            │        │
│       ├─→ 质量达标 → 进入下一层追问 ───────────────┘        │
│       │                                                    │
│       └─→ 质量不达标 → 重新生成ToDo                         │
│                                                            │
│   终止条件：                                                │
│   1. 到达第5层（护城河不可复制性）且证据充分                 │
│   2. 连续N次无法获取新证据                                  │
│   3. 所有追问都有充分证据支撑                                │
│                                                            │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 ToDo类型

```
ToDo类型：
├─ 数据验证类
│   ├─ 从现有数据中重新提取依据
│   ├─ 交叉验证关键数据
│   └─ 标注数据来源和质量
```

```python
class FinancialDataValidator:
    """财务数据质量验证器"""
    
    def validate_data_quality(self, data_point: dict) -> dict:
        """对单个数据点进行否定之否定验证"""
        
        # 第一步：收集初始数据
        initial_data = self._collect_initial_data(data_point)
        
        # 第二步：否定（生成质疑）
        doubts = self._generate_doubts(initial_data)
        
        # 第三步：验证质疑
        validation_results = []
        for doubt in doubts:
            result = self._validate_doubt(doubt, initial_data)
            validation_results.append(result)
        
        # 第四步：否定之否定（确认质量）
        quality_score = self._calculate_quality_score(validation_results)
        
        return {
            "quality_score": quality_score,
            "quality_label": self._determine_quality_label(quality_score),
            "todos": self._extract_todos(validation_results)
        }


class MoatQuestioningEngine:
```
