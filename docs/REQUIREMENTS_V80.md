# Company Deep Analysis V8.0 需求文档

## 一、项目概述

### 1.1 项目名称
Company Deep Analysis Skill V8.0 - 多阶段深度投资分析

### 1.2 项目目标
基于 V7.0 的核心设计，通过**多阶段架构**解决上下文膨胀和质量不可控问题：

- **多阶段执行** - 每个阶段聚焦单一任务，上下文精简
- **阶段质量门禁** - 每阶段有明确的检验标准和通过条件
- **状态持久化** - 中间结果可保存、可恢复、可调试
- **准确性优先** - 数据质量把控，宁慢勿错

### 1.3 与 V7.0 的关系

| 方面 | V7.0 | V8.0 |
|------|------|------|
| **核心理念** | 相同 | 相同 |
| **五层追问** | ✅ 保留 | ✅ 保留 |
| **否定之否定** | ✅ 保留 | ✅ 强化 |
| **奖励函数** | ✅ 保留 | ✅ 简化 |
| **执行方式** | 单次执行 | 多阶段分离 |
| **质量把控** | 无检验 | 每阶段门禁 |
| **可恢复性** | 不可恢复 | 可从任意阶段继续 |

### 1.4 核心原则

1. **准确性优先于速度** - 宁可慢，也要准
2. **数据质量第一** - 财务数据必须经过严格验证
3. **阶段独立可测试** - 每个阶段可单独运行和验证
4. **证据驱动结论** - 每个结论都有数据支撑

## 二、多阶段架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    V8.0 多阶段架构                           │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  阶段1: 数据收集与质量验证                                    │
│  ├─ 输入: company, ticker, market                           │
│  ├─ 处理: 收集财务数据 + 质量验证                            │
│  ├─ 检验: 核心指标 >= 4, P0级数据源存在                      │
│  └─ 输出: verified_data, quality_gate                       │
│      ↓                                                      │
│  阶段2: 财务异常分析                                         │
│  ├─ 输入: stage1_result                                     │
│  ├─ 处理: 检测异常 + 生成追问                                │
│  ├─ 检验: 异常 >= 1, 追问具体                                │
│  └─ 输出: anomalies, primary_question                       │
│      ↓                                                      │
│  阶段3: 经营分析                                             │
│  ├─ 输入: stage1_result, stage2_result                      │
│  ├─ 处理: 行业对比 + 洞察生成                                │
│  ├─ 检验: 洞察 >= 2, 识别核心能力                            │
│  └─ 输出: insights, core_capability                         │
│      ↓                                                      │
│  阶段4: 护城河识别                                           │
│  ├─ 输入: stage1_result, stage3_result                      │
│  ├─ 处理: 护城河分类 + 证据收集                              │
│  ├─ 检验: 类型明确, 置信度 >= 0.7, 证据 >= 2                │
│  └─ 输出: moat_type, confidence, evidence                   │
│      ↓                                                      │
│  阶段5: 不可复制性分析                                       │
│  ├─ 输入: stage4_result                                     │
│  ├─ 处理: 可持续性评估 + 风险识别                            │
│  ├─ 检验: 可持续性评级, 理由 >= 2, 风险 >= 1                │
│  └─ 输出: sustainability, reasons, risks, conclusion        │
│      ↓                                                      │
│  阶段6: 报告生成                                             │
│  ├─ 输入: 所有前置阶段结果                                   │
│  ├─ 处理: 整合 + 格式化 + 上传                               │
│  ├─ 检验: 报告完整, 无截断                                   │
│  └─ 输出: Markdown报告 + Gist链接                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 阶段独立性

每个阶段满足：
- **独立输入** - 可从前置阶段结果读取
- **独立输出** - 生成结构化 JSON
- **独立检验** - 有明确的质量门禁
- **独立恢复** - 可从任意阶段继续执行

## 三、阶段详细设计

### 3.1 阶段1：数据收集与质量验证

#### 职责
- 从多数据源收集财务数据
- 验证数据质量（范围验证、来源验证）
- 输出已验证的核心财务数据

#### 输入
```json
{
  "company": "PDD Holdings",
  "ticker": "PDD",
  "market": "us"
}
```

#### 输出
```json
{
  "stage": "data_collection",
  "status": "success",
  "timestamp": "2026-03-14T15:22:31",
  "company": "PDD Holdings",
  "ticker": "PDD",
  "market": "us",
  
  "verified_data": [
    {
      "name": "ROE",
      "value": 44.92,
      "source": "AkShare-东方财富",
      "quality": "P0",
      "validation": {
        "range_check": true,
        "source_quality": "P0",
        "passed": true
      }
    }
  ],
  
  "total_collected": 8,
  "total_verified": 8,
  
  "quality_gate": {
    "passed": true,
    "criteria": {
      "min_core_metrics": 4,
      "required_sources": ["P0"]
    },
    "issues": []
  },
  
  "next_action": "stage2"
}
```

#### 数据验证规则

| 验证类型 | 描述 | 处理 |
|----------|------|------|
| **范围验证** | 数值在合理区间内 | 超出范围标记警告 |
| **来源验证** | 数据来源质量评级 | P0/P1/P2/P3 分级 |
| **交叉验证** | 多源数据对比 | 差异过大标记 |

#### 质量门禁标准
- ✅ 核心财务指标 >= 4 个
- ✅ 必须有 P0 级数据源
- ✅ 必需指标缺失 <= 2 个

---

### 3.2 阶段2：财务异常分析

#### 职责
- 检测财务数据异常
- 为每个异常生成深度追问
- 追问必须指向具体经营层面

#### 输入
阶段1的 verified_data

#### 输出
```json
{
  "stage": "financial_anomaly",
  "status": "success",
  "timestamp": "2026-03-14T15:23:56",
  "company": "PDD Holdings",
  
  "financial_data": {
    "ROE": 44.92,
    "毛利率": 60.92
  },
  
  "anomalies": [
    {
      "metric": "ROE",
      "value": 44.92,
      "severity": "high",
      "description": "ROE 44.9% 显著高于行业均值（约30%）",
      "question": "高ROE是否主要源于高财务杠杆、资产周转加速，还是净利润率异常提升？"
    }
  ],
  
  "primary_question": "ROE 44.9% 显著高于行业均值，核心驱动因素是什么？",
  
  "quality_gate": {
    "passed": true,
    "issues": []
  },
  
  "next_action": "stage3"
}
```

#### 异常检测阈值

| 指标 | 高阈值 | 低阈值 | 说明 |
|------|--------|--------|------|
| ROE | 30% | 0% | 高于30%视为异常 |
| 毛利率 | 60% | 10% | 行业对比 |
| 净利润增速 | 100% | -50% | 大幅波动 |

#### 质量门禁标准
- ✅ 至少发现 1 个异常（或确认无异常）
- ✅ 每个异常有具体追问
- ✅ 追问长度 >= 10 字符

---

### 3.3 阶段3：经营分析

#### 职责
- 搜索行业对比数据
- 生成经营洞察
- 识别核心经营能力

#### 输入
阶段1财务数据 + 阶段2异常列表

#### 输出
```json
{
  "stage": "business_analysis",
  "status": "success",
  "timestamp": "2026-03-14T15:24:32",
  "company": "PDD Holdings",
  
  "core_capability": "高定价权与卓越成本管控能力",
  
  "insights": [
    {
      "content": "ROE显著偏高，反映公司高效利用股东资金...",
      "evidence": ["ROE=44.92%"],
      "source": "LLM分析+财务数据",
      "quality": "P1"
    }
  ],
  
  "industry_comparison": {
    "data": ["行业数据..."]
  },
  
  "quality_gate": {
    "passed": true,
    "issues": []
  },
  
  "next_action": "stage4"
}
```

#### 质量门禁标准
- ✅ 洞察数量 >= 2
- ✅ 识别出核心经营能力
- ✅ 每条洞察有证据支撑

---

### 3.4 阶段4：护城河识别

#### 职责
- 识别护城河类型（五大类型之一）
- 收集验证证据
- 计算置信度

#### 护城河五大类型

| 类型 | 核心问题 | 验证数据 |
|------|----------|----------|
| **网络效应** | 用户越多，价值是否越大？ | 获客成本、用户留存 |
| **转换成本** | 客户换掉我们会损失什么？ | 客户留存率、续约率 |
| **成本优势** | 低成本来自哪里？ | 毛利率对比、单位成本 |
| **无形资产** | 品牌/专利能带来定价权吗？ | 品牌溢价、专利数量 |
| **有效规模** | 新进入者会破坏均衡吗？ | ROIC对比、竞争者数量 |

#### 输出
```json
{
  "stage": "moat_identification",
  "status": "success",
  "timestamp": "2026-03-14T15:25:18",
  "company": "PDD Holdings",
  
  "moat_type": "成本优势",
  "confidence": 0.85,
  
  "evidence": [
    "毛利率 60.9%，显著高于行业均值",
    "ROE 44.9%，资本效率高"
  ],
  
  "verification_questions": [
    "低成本来自规模、资源、地理位置还是流程？",
    "竞争对手能否复制这个成本结构？"
  ],
  
  "quality_gate": {
    "passed": true,
    "issues": []
  },
  
  "next_action": "stage5"
}
```

#### 质量门禁标准
- ✅ 护城河类型明确（非"未识别"）
- ✅ 置信度 >= 0.7
- ✅ 证据数量 >= 2

---

### 3.5 阶段5：不可复制性分析

#### 职责
- 评估护城河可持续性
- 识别风险因素
- 生成最终结论

#### 可持续性评级标准

| 评级 | 时间框架 | 标准 |
|------|----------|------|
| **强** | 5年以上 | 竞争对手无法在短期内复制 |
| **中** | 3-5年 | 竞争对手需要大量投入才能复制 |
| **弱** | 1-3年 | 竞争对手可能快速追赶 |

#### 输出
```json
{
  "stage": "sustainability",
  "status": "success",
  "timestamp": "2026-03-14T15:26:45",
  "company": "PDD Holdings",
  
  "moat_type": "成本优势",
  "sustainability": "中",

    "该模式已被头部对手局部复现"
  ],
  
  "risks": [
    "竞争对手可能通过技术创新降低成本",
    "原材料价格波动可能侵蚀利润"
  ],
  
  "conclusion": "PDD Holdings的成本优势护城河具有一定可持续性，但需关注竞争态势变化。",
  
  "quality_gate": {
    "passed": true,
    "issues": []
  },
  
  "next_action": "stage6"
}
```

#### 质量门禁标准
- ✅ 可持续性评级明确
- ✅ 支撑理由 >= 2
- ✅ 风险因素 >= 1
- ✅ 结论完整

```
company-deep-analysis/
```

### 4.2 执行方式

#### 完整执行
```bash
python run_v80.py --company "PDD Holdings" --ticker PDD --market us
```

#### 单阶段执行
```bash
python run_v80.py --company "PDD Holdings" --ticker PDD --market us --stop-at 3
```

#### 从指定阶段继续
```bash
python run_v80.py --state ./state/PDD_20260314 --from-stage 4
```

### 4.3 状态持久化

每个阶段完成后：
1. 生成 JSON 结果文件
2. 保存到 state/{company}_{timestamp}/ 目录
3. 文件名格式: stage{N}_{timestamp}.json

## 五、质量把控体系

### 5.1 数据源质量分级

| 等级 | 定义 | 数据源 |
|------|------|--------|
| **P0** | 官方一手数据 | 年报/10-K、AkShare-东方财富 |
| **P1** | 权威第三方 | Bloomberg、雪球公告 |
| **P2** | 专业机构 | Tavily、Exa搜索、雪球专栏 |
| **P3** | 媒体报道 | 财经媒体 |

### 5.2 阶段质量门禁汇总

| 阶段 | 检验项 | 通过标准 |
|------|--------|----------|
| **阶段1** | 核心指标数 | >= 4 |
| **阶段1** | P0数据源 | 必须存在 |
| **阶段2** | 异常数量 | >= 1 |
| **阶段2** | 追问具体性 | >= 10字符 |
| **阶段3** | 洞察数量 | >= 2 |
| **阶段3** | 核心能力 | 已识别 |
| **阶段4** | 护城河类型 | 明确 |
| **阶段4** | 置信度 | >= 0.7 |
| **阶段4** | 证据数 | >= 2 |
| **阶段5** | 可持续性 | 已评级 |
| **阶段5** | 理由数 | >= 2 |
| **阶段5** | 风险数 | >= 1 |
| **阶段6** | 报告完整性 | 结构完整 |
| **阶段6** | Gist上传 | 成功 |

## 七、与 V7.0 的对比总结

| 方面 | V7.0 问题 | V8.0 解决 |
|------|-----------|-----------|
| **执行方式** | 单次执行，上下文膨胀 | 多阶段分离，上下文聚焦 |
