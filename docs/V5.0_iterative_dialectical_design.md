## 一、问题背景

### 1.1 当前框架的问题

**V4.x 的线性流程**：

```
数据收集 → 财务分析 → 护城河分析 → 估值 → 结论
   ↑
一次性收集，后续分析靠"脑拍"
```

**核心问题**：

| 问题 | 表现 | 影响 |
|------|------|------|
| **数据收集无针对性** | 一开始就收集所有数据 | 收集了大量无用信息，关键信息反而缺失 |
| **辩证缺乏证据支撑** | 第二轮反题时靠"推测" | 结论可能脱离事实 |
| **疑点无验证机制** | 发现疑点后没有后续 | 疑点被忽略，分析不完整 |
| **一次性思维** | 假设一次收集完就能分析到底 | 不符合真实分析师思维 |

### 1.2 真实分析师的思维模式

```
分析师的一天：

上午：
  "看财报，利润下滑30%，初步判断：护城河消失"
  ↓
  "等等，现金流反而增长了？这不合理..."
  ↓
  针对性搜索："为什么利润下滑但现金流增长？"
  ↓
  发现：是因为应付账款增加，占用供应商资金
  
下午：
  "那这是好事还是坏事？"
  ↓
  针对性搜索："占用供应商资金的风险"
  ↓
  发现：如果议价能力强，这是好事；如果只是延迟付款，风险很大
  
晚上：
  "需要验证议价能力"
  ↓
  针对性搜索："公司市场份额变化、客户流失率"
  ↓
  发现：市场份额在下滑，议价能力存疑
  
结论：
  "利润下滑+现金流增长"看似矛盾，实则揭示了议价能力下降的问题
  这比简单的"护城河消失"更深入
```

**关键特征**：
1. **疑点驱动**：每个搜索都源于具体的疑问
2. **目标明确**：搜索是为了证明或否定某个判断
3. **迭代深入**：发现新问题，继续深入
4. **证据支撑**：每个结论都有证据，不是脑拍

## 二、设计目标

### 2.1 核心目标

将**线性分析流程**改造为**迭代式辩证分析流程**，使每一轮辩证都有针对性数据支撑。

### 2.2 具体目标

| 目标 | 说明 | 衡量标准 |
|------|------|----------|
| **疑点驱动** | 每轮搜索都源于具体疑问 | 搜索查询包含明确的验证目的 |
| **证据支撑** | 每个判断都有证据来源 | 结论都有"证据来源"标注 |
| **迭代深入** | 发现疑点后继续深入 | 平均每家公司触发3-5轮检索 |
| **过程透明** | 分析过程可追溯 | 输出完整的分析链路 |

### 2.3 非目标

- 不是要完全自动化（仍需人工判断）
- 不是要收集所有可能的数据（按需收集）
- 不是要消除不确定性（而是更好地理解不确定性）

## 三、核心概念

### 3.1 迭代式辩证分析

**定义**：一种以疑点为驱动、以证据为支撑、循环迭代的分析方法。

**核心要素**：

```
┌─────────────────────────────────────────────┐
│                                             │
│   假设 (Hypothesis)                         │
│     ↓                                       │
│   疑点 (Doubt) ← 发现不合理/不确定之处       │
│     ↓                                       │
│   检索目标 (Search Target) ← 明确要找什么    │
│     ↓                                       │
│   证据 (Evidence) ← 搜索结果                 │
│     ↓                                       │
│   验证/否定 (Validate/Invalidate)            │
│     ↓                                       │
│   修正假设 (Updated Hypothesis)              │
│     ↓                                       │
│   回到顶部，继续下一轮                       │
│                                             │
└─────────────────────────────────────────────┘
```

### 3.2 疑点 (Doubt)

**定义**：分析过程中发现的不合理、不确定、需要进一步验证的问题。

**疑点类型**：

| 类型 | 说明 | 示例 |
|------|------|------|
| **数据矛盾** | 两个数据/结论相互矛盾 | 利润下滑30%，但现金流增长20% |
| **逻辑断裂** | A→B的逻辑链条不完整 | 为什么高ROE就是好公司？ |
| **反例存在** | 存在与结论相反的案例 | 公司护城河强，但市场份额下滑 |
| **信息缺失** | 关键信息无法验证 | 管理层激励是否到位？ |
| **假设过强** | 前提假设未经证实 | 假设行业会持续增长 |

**疑点优先级**：

| 优先级 | 条件 |
|--------|------|
| P0 | 直接影响核心结论 |
| P1 | 影响次要结论 |
| P2 | 补充性信息 |

### 3.3 检索目标 (Search Target)

**定义**：为了验证/否定疑点，需要寻找的具体信息。

**目标结构**：

```json
{
  "doubt_id": "D001",
  "doubt_type": "数据矛盾",
  "doubt_description": "利润下滑30%，现金流增长20%，矛盾",
  "search_purpose": "验证现金流增长的真实原因",
  "search_query": "Fiserv 2025 profit decline cash flow increase reason",
  "expected_evidence": "财报说明、分析师评论、行业报告",
  "success_criteria": "找到合理解释，或确认数据有误"
}
```

### 3.4 证据 (Evidence)

**定义**：通过搜索获得的支持或否定假设的信息。

**证据属性**：

| 属性 | 说明 |
|------|------|
| 来源 | 哪里找到的（URL/文档） |
| 可信度 | 来源的可靠性（P0-P4） |
| 相关性 | 与疑点的关联程度 |
| 支持方向 | 支持/否定/中立 |

**证据评估**：

```
证据可信度分级：
- P0（官方文件）：财报、监管文件、公司公告
- P1（权威媒体）：WSJ、Reuters、Bloomberg
- P2（专业分析）：行业报告、分析师报告
- P3（大众媒体）：一般新闻、博客
- P4（社交媒体）：讨论、评论
```

## 四、分析流程设计

### 4.1 整体流程

```
┌──────────────────────────────────────────────────────────────────┐
│                    迭代式辩证分析流程                              │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌─────────────┐                                                │
│  │ 1. 初始假设  │ ← 基于基本财务数据                              │
│  └──────┬──────┘                                                │
│         ↓                                                        │
│  ┌─────────────┐                                                │
│  │ 2. 识别疑点  │ ← 发现不合理/不确定之处                         │
│  └──────┬──────┘                                                │
│         ↓                                                        │
│    ┌────┴────┐                                                  │
│    │ 有疑点？ │                                                  │
│    └────┬────┘                                                  │
│      是 │ 否                                                    │
│         ↓  └─────────→ 输出最终结论                              │
│  ┌─────────────┐                                                │
│  │ 3. 生成检索  │ ← 为每个疑点生成搜索目标                        │
│  │    目标     │                                                 │
│  └──────┬──────┘                                                │
│         ↓                                                        │
│  ┌─────────────┐                                                │
│  │ 4. 执行检索  │ ← 带目的的搜索                                  │
│  └──────┬──────┘                                                │
│         ↓                                                        │
│  ┌─────────────┐                                                │
│  │ 5. 评估证据  │ ← 判断证据是否支持/否定假设                     │
│  └──────┬──────┘                                                │
│         ↓                                                        │
│  ┌─────────────┐                                                │
│  │ 6. 修正假设  │ ← 根据证据更新判断                              │
│  └──────┬──────┘                                                │
│         │                                                        │
│         └──────────→ 返回步骤2                                   │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

### 4.2 详细步骤

#### Step 1: 初始假设

**输入**：公司名称/代码
**输出**：初步判断（Hypothesis V0）

**活动**：
1. 获取基本财务数据（营收、利润、ROIC等）
2. 形成初步印象
3. 输出初始假设

**示例**：
```
公司：Fiserv (FISV)
财务数据：
  - 营收：$21.2B，增速3.6%
  - 净利润：$2.2B
  - ROIC：8.7%
  - 净债务：$28.2B

初始假设 V0：
  "Fiserv增长缓慢（3.6%），ROIC较低（8.7%），
   高债务（$28.2B），初步判断：不值得投资"
```

#### Step 2: 识别疑点

**输入**：当前假设
**输出**：疑点列表（Doubt List）

**活动**：
1. 审视假设的每个组成部分
2. 识别不合理、不确定之处
3. 按优先级排序

**示例**：
```
当前假设：Fiserv不值得投资

疑点识别：
  D001 [P0] 数据矛盾：
    - 利润增速11%，但营收增速仅3.6%
    - 为什么利润增速远高于营收增速？
  
  D002 [P1] 逻辑断裂：
    - ROIC 8.7%，是否真的"低"？
    - WACC是多少？如果WACC<8.7%，那ROIC并不低
  
  D003 [P1] 信息缺失：
    - 高债务是否可控？
    - 利息保障倍数是多少？
  
  D004 [P2] 反例存在：
    - 增长慢的公司一定不值得投资吗？
    - 是否有类似的困境反转成功案例？
```

#### Step 3: 生成检索目标

**输入**：疑点列表
**输出**：检索目标列表（Search Target List）

**活动**：
1. 为每个疑点生成搜索查询
2. 明确期望的证据类型
3. 设定成功标准

**示例**：
```
疑点 D001：利润增速11%，营收增速3.6%，为什么？

检索目标：
  - purpose: "验证利润增速高于营收增速的原因"
  - query: "Fiserv profit margin expansion 2025 EPS growth driver"
  - expected: "财报说明、分析师解读"
  - success: "找到利润率扩张的具体原因"

疑点 D002：ROIC 8.7%是否真的低？

检索目标：
  - purpose: "确定Fiserv的WACC"
  - query: "Fiserv WACC cost of capital debt interest rate"
  - expected: "分析师报告、财务数据"
  - success: "找到WACC数值或计算所需数据"
```

#### Step 4: 执行检索

**输入**：检索目标
**输出**：证据列表（Evidence List）

**活动**：
1. 执行搜索（Tavily/Exa）
2. 提取相关内容
3. 评估可信度

**示例**：
```
执行搜索：Fiserv profit margin expansion 2025

证据 E001：
  - source: "Seeking Alpha分析文章"
  - credibility: P2
  - content: "利润率扩张主要来自股票回购，
              2025年回购了$4B股票，减少股本10%"
  - direction: 支持 D001 的验证

证据 E002：
  - source: "Fiserv官方财报"
  - credibility: P0
  - content: "调整后营业利润率从20%提升至22%"
  - direction: 补充信息
```

#### Step 5: 评估证据

**输入**：证据列表 + 当前假设
**输出**：验证结果（Validation Result）

**活动**：
1. 判断证据是否支持/否定疑点
2. 更新对疑点的理解
3. 决定是否需要更多证据

**示例**：
```
评估 D001（利润增速高于营收增速）：

证据总结：
  - 利润率扩张：20% → 22%（内生改善）
  - 股票回购：$4B，减少股本10%（财务工程）
  
验证结果：
  - D001 已解决
  - 原因：内生改善 + 财务工程共同作用
  - 影响：利润增速高于营收增速是合理的
  
新认识：
  - 公司在利润率改善方面做得不错
  - 但过度依赖回购也有风险
  - 需要进一步验证：回购的资金来源（债务？现金流？）
```

#### Step 6: 修正假设

**输入**：验证结果
**输出**：更新后的假设（Hypothesis V1）

**活动**：
1. 根据新证据更新判断
2. 可能产生新的疑点
3. 准备下一轮迭代

**示例**：
```
假设更新：

V0: "Fiserv不值得投资（增长慢、ROIC低、高债务）"

V1: "Fiserv有一定投资价值，但需谨慎
     - 增长慢但利润率在改善（内生+回购）
     - ROIC 8.7%需与WACC比较后判断
     - 高债务需验证利息保障能力
     - 关键风险：回购依赖债务融资"

新疑点：
  D005 [P0]: 回购的资金来源？
  D006 [P1]: 债务结构如何？是否有到期压力？
```

### 4.3 迭代控制机制

#### 4.3.1 循环次数设置

| 参数 | 值 | 说明 |
|------|-----|------|
| **最大循环次数** | 15-20次 | 足够深入，避免过早终止 |
| **最小循环次数** | 3次 | 确保基本分析深度 |

#### 4.3.2 每轮评分机制

**目的**：评估当前分析是否足够扎实充分，核心问题是否已解决。

**评分模型**（参考雪球分析评分系统）：

| 维度 | 满分 | 评分标准 |
|------|------|----------|
| **假设完整性** | 25分 | 假设是否涵盖核心投资逻辑？ |
| **证据充分性** | 25分 | 每个关键判断是否有证据支撑？ |
| **疑点解决率** | 25分 | 已解决疑点占比？ |
| **逻辑一致性** | 15分 | 结论与证据是否一致？ |
| **深度分析** | 10分 | 是否触及本质问题？ |
| **总分** | 100分 | - |

**评分阈值**：

| 分数区间 | 判定 | 行动 |
|----------|------|------|
| ≥ 85分 | 充分 | ✅ 可以终止分析 |
| 70-84分 | 基本充分 | 建议1-2轮补充 |
| < 70分 | 不足 | 继续迭代 |

#### 4.3.3 终止条件（综合判断）

| 条件 | 权重 | 说明 |
|------|------|------|
| **评分达标** | 50% | 评分≥85分 |
| **疑点解决率** | 30% | ≥80%疑点已解决 |
| **无新疑点** | 20% | 连续2轮无新P0/P1疑点 |

**终止判定逻辑**：
```python
def should_terminate(analysis_state):
    # 1. 强制终止条件
    if analysis_state.iteration >= MAX_ITERATIONS:  # 15-20次
        return True
    
    # 2. 评分达标终止
    if analysis_state.score >= 85:
        return True
    
    # 3. 综合判定
    score_weight = 0.5 if analysis_state.score >= 85 else 0
    resolution_weight = 0.3 if analysis_state.resolved_ratio >= 0.8 else 0
    no_new_doubts = 0.2 if analysis_state.no_new_doubts_rounds >= 2 else 0
    
    return (score_weight + resolution_weight + no_new_doubts) >= 0.7
```

## 五、技术实现方案

### 5.1 核心设计理念：LLM优先

**设计原则**：以LLM为核心驱动，而非规则引擎。LLM具备：
- 敏锐发现问题的能力
- 深度质疑的能力
- 独立评分的能力
- 提出解决方案的能力

**双LLM协作架构**（否定之否定）：

```
┌─────────────────────────────────────────────────────────────────┐
│                    双LLM协作架构                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │                    LLM-1: 质疑者                           │  │
│  │                                                            │  │
│  │  角色：资深价值投资分析师，以批判性思维著称                  │  │
│  │                                                            │  │
│  │  职责：                                                    │  │
│  │  • 发现分析中的漏洞和疑点                                  │  │
│  │  • 提出尖锐的质疑                                          │  │
│  │  • 对当前分析进行独立评分                                  │  │
│  │  • 挑战假设的合理性                                        │  │
│  │                                                            │  │
│  │  输出：                                                    │  │
│  │  • 疑点列表（带优先级）                                    │  │
│  │  • 分析评分（0-100分）                                     │  │

│                              │                                  │

│  │                                                            │  │
│  │  职责：                                                    │  │

│  │                                                            │  │
│  │  输出：                                                    │  │
│  │  • 检索目标（带目的）                                      │  │

│                                                                 │

def select_data_sources(doubt_type: DoubtType, query: str) -> List[DataSource]:
    """根据疑点类型选择数据源"""
    
    sources = []
    
    # 财务数据相关
    if doubt_type in [DoubtType.DATA_CONTRADICTION, DoubtType.MISSING_INFO]:
        if is_financial_query(query):
            sources.append(AkShareSource())  # 财务数据优先
    
    # 中文内容相关
    if contains_chinese(query) or is_china_stock(query):
        sources.append(XueqiuSource())  # 雪球优先
    
    # 实时信息相关
    if doubt_type == DoubtType.COUNTEREXAMPLE:
        sources.append(TavilySource())  # 实时搜索
    
    # 深度研究相关
    if doubt_type == DoubtType.LOGIC_GAP:
        sources.append(ExaSource())  # 深度研究
    
    # 默认：通用搜索
    if not sources:
        sources = [TavilySource(), ExaSource()]
    
    return sources
```

## 九、风险与限制

### 9.1 技术风险

| 风险 | 影响 | 缓解措施 |
