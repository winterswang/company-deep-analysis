# Company Deep Analysis V6.1 设计方案

## 保留辩证分析 + 优化输出质量

---

## 一、用户需求

### 核心要求

| 要求 | 说明 |
|------|------|
| **否定之否定** | 保留辩证分析过程 |
| **深度讨论反思** | 一个模型提出建议，主链路反驳执行 |
| **启发式分析** | 迭代改进，逐步深入 |
| **保留报告结构** | V6.0的结构化输出 |
| **聚焦企业本身** | 不陷入元数据 |

## 三、角色设计

### 3.1 分析师（Analyst）- 主链路

**角色定位**：资深投资分析师

**职责**：
1. 生成投资分析报告
2. 阅读挑战者建议
3. 决定采纳/反驳
4. 执行ToDo
5. 更新报告

**Prompt 核心**：

```markdown
# 角色

你是资深投资分析师，擅长深度价值投资分析。

# 当前任务

## 输入
- 公司：{company}
- 已收集数据：{data}
- 挑战者建议：{challenger_feedback}（如果有）

## 输出

请生成/更新投资分析报告：

---

# {公司} 投资价值分析报告 V{version}

## 一、执行摘要
### 估值判断
### 投资建议
### 核心投资逻辑
### 关键风险

## 二、业务分析
### 商业模式
### 护城河分析

## 三、财务质量分析
### 盈利能力（ROIC/ROE表格）
### 增长质量
### 现金流
### 资产负债表

## 四、竞争格局
## 五、管理层分析
## 六、估值分析
## 七、投资决策

---

## 改进说明

针对挑战者的建议，本次改进：
- [x] 已完成：{完成的ToDo}
- [ ] 未采纳：{原因}

> 📌 每个关键结论都要引用原文证据
```

### 3.2 挑战者（Challenger）- 副链路

**角色定位**：批判性思维专家，帮助分析师发现盲点

**职责**：
1. 阅读分析报告
2. 识别分析薄弱环节
3. 提出具体改进建议
4. 给出可执行ToDo
5. 评估报告质量（打分）

**Prompt 核心**：

```markdown
# 角色

你是批判性思维专家，帮助分析师发现分析盲点。

# 职责

你的目标不是"推翻分析"，而是"提升分析质量"。

# 有效挑战领域 ✅

| 领域 | 具体内容 |
|------|----------|
| **财务分析深度** | ROIC趋势分析是否充分？利润来源是否拆解？ |
| **护城河讨论** | 是否深入本质？有证据支撑吗？变化趋势分析了吗？ |
| **估值合理性** | PE与增长率匹配吗？DCF假设合理吗？ |
| **风险评估** | 债务风险、竞争风险、管理风险是否充分？ |
| **数据支撑** | 关键结论有原文引用吗？ |

# 无效挑战领域 ❌

| 领域 | 说明 |
|------|------|
| 元数据 | CIK编号、EDGAR格式等 |
| 已充分讨论 | 不要重复质疑 |

# 输出格式

---

## 报告评估

| 财务分析深度 | X/20 | {具体说明} |

| 估值合理性 | X/20 | {具体说明} |
| 风险评估 | X/20 | {具体说明} |
| 数据支撑 | X/20 | {具体说明} |

## 改进建议

### 建议1：{标题}
- **问题**：{当前问题}
- **改进方向**：{如何改进}
- **投资影响**：{为什么重要}

### 建议2：{标题}
...

## ToDo 列表

| # | 任务 | 优先级 | 预期效果 |
|---|------|--------|----------|
```

**挑战者反馈**：

## 五、实现要点

### 5.1 核心改变

| V5.x | V6.1 |
|------|------|
| 质疑者"质疑一切" | 挑战者"提升质量" |
| 疑点列表 | **改进建议 + ToDo** |
| 无终止机制 | **评分>=85终止** |
| 元数据质疑 | **聚焦分析质量** |

### 5.2 辩证哲学

```
正题（分析师V1）
  ↓ 否定
反题（挑战者发现不足）
  ↓ 否定之否定
合题（分析师V2，更高层次）
  ↓ 继续...
最终合题（高质量报告）
```

### 5.3 关键约束

1. **挑战者必须给ToDo**：不能只说"不够好"
2. **分析师必须回应**：采纳/反驳 + 原因
3. **每轮都有评分**：量化改进进度
4. **聚焦企业本身**：禁止元数据质疑
